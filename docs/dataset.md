# Dataset

Dataset entries are immutable once published. Each entry includes source language, target language, source code, target code, source and target context, direction, verification data, provenance, feature tags, difficulty, and metadata.

Entries are content-addressable where practical. Splits are generated by repository and deduplication lineage, not by random function extraction. Permanent held-out benchmarks never enter training. Rejected candidates are stored separately because they support ranking, preference, and repair training.

## Storage

- `raw/`
- `normalized/`
- `generated/`
- `verified/`
- `rejected/`

Only manifests and small fixtures belong in git. Large datasets remain outside git.
