# Independent review report — CodeMorph-Product (dev)

Scope: entire repository (crates, python, docs) as Phase 8 cross-cutting self-critique. Reviewed against `AGENTS.md`, `docs/architecture.md`, `docs/USAGE.md`, `docs/migration-engine.md`, and the staged contracts in `crates/codemorph-cli/tests/migrate_contract.rs`. Build verified: `cargo fmt --check`, `cargo clippy --workspace -- -D warnings`, and `cargo test --workspace` all pass (PATH includes ~/.cargo/bin). Python toolchain (pytest/ruff/mypy) is not installed in this environment, so python checks were not executed.

Verdict: CHANGES REQUESTED

Checklist used: General, Auth/Security (sandbox/execution), Tests

## Findings

- [severity: major] [confidence: HIGH] `crates/codemorph-core/src/verification.rs:6-7` — `VerificationResult` carries source-language-specific field names (`cpp_compiles`, `rust_compiles`) in generic core. AGENTS.md/architecture.md require generic core to name no language-specific concept; this leaks the C++/Rust direction into the supposedly language-agnostic core. Any future direction must either rename or reuse these fields misleadingly. → Recommendation: rename to source/target-agnostic booleans (e.g. `source_compiles`/`target_compiles`) or generic compile-stage booleans, and update all producers/consumers and serialized artifacts with a schema-version bump.
- [severity: major] [confidence: HIGH] `crates/codemorph-sandbox/src/lib.rs:10-14` (limit fields defined in `crates/codemorph-core/src/sandbox.rs:8-11`) — `ExecutionLimits` declares `memory_bytes`, `cpu_seconds`, `network_enabled`, and `filesystem_root`, but `Sandbox::execute` only enforces `timeout_ms` (and byte caps on captured output). Memory/CPU/network/filesystem restrictions are silently ignored while untrusted generated C++/Rust binaries and Python model backends run as full-access child processes. This contradicts the documented sandbox/security contract (AGENTS.md “Sandbox is the only approved path… Process, CPU, memory, filesystem, network, and timeout limits apply”). → Recommendation: document that the current sandbox is timeout-only until OS limits are implemented, OR implement rlimits/seccomp/chroot/namespace isolation; at minimum make unsupported limits a hard error rather than silently no-ops.
- [severity: major] [confidence: HIGH] `crates/codemorph-cli/src/commands.rs:106` — during compile repair, the local proposer is explicitly disabled: `generate_translation(&repair_prompt, false, allow_ollama)`. `docs/specialized-models.md` claims a `repair` role hook exists (“invoked on compile failure via repair hook”), but with `allow_local=false` the repair role can never be consulted; repair only ever uses Ollama. The documented specialized-model contract is therefore not actually wired. → Recommendation: pass the repair role/local backend through (role-specific directory + model) and test that `repair` is exercised when `CODEMORPH_USE_MODEL=1` and a repair manifest exists; otherwise relabel the hook “reserved” in docs.
- [severity: major] [confidence: MEDIUM] `crates/codemorph-cli/src/translate.rs:16` — the entire deterministic translator (2380 lines of tokenizer/parser/codegen) lives inside the CLI crate, and `codemorph-orchestrate` (`crates/codemorph-orchestrate/src/lib.rs`) is only an in-memory state machine with no use of it. `docs/migration-engine.md` describes an engine that “receives a minimal relevant context… Budgets limit candidates…”, but the actual migration runs monolithically in `commands::migrate`/`translate_one` with effectively no per-unit state persistence or reuse beyond JSON artifacts. → Recommendation: move parser/codegen into `codemorph-cpp`/a translation crate and have the CLI call a library API; wire budget enforcement and unit persistence into `codemorph-orchestrate` before calling it a migration engine (or narrow the docs to “CLI monolith”).
- [severity: major] [confidence: MEDIUM] `crates/codemorph-cli/src/commands.rs:478-482` — `--include-stages` and `--skip-stages` are accepted as CLI options but deliberately discarded (`let _ = ...`). Users cannot actually include/skip stages despite the flag surface, and docs imply stage selectivity. → Recommendation: implement filtering (or remove the flags and document only `--stage`). Add a test asserting unknown/filtered stage behavior.
- [severity: major] [confidence: MEDIUM] `crates/codemorph-sandbox/src/lib.rs:10` + `crates/codemorph-rustlang/src/lib.rs` compiler discovery — sandbox always succeeds in launching whatever path/args; Rust discovery prefers a rustup toolchain directory via string scan and otherwise only checks fixed paths, so non-rustup installs (e.g. `/usr/bin/rustc`) can silently fail to locate a working compiler. Combined with `.unwrap()` in `benchmark` (`commands.rs:1019`, `commands.rs:1034`), a spawn/toolchain failure panics instead of returning a typed error. → Recommendation: use `which`/PATH lookup without the rustup-only heuristic, propagate sandbox errors as `CoreError`, and replace panicking `.unwrap()` with error reporting.


## Minor

- [severity: minor] [confidence: HIGH] `crates/codemorph-cli/src/commands.rs:494` (`_ => {}`) — an unrecognized `--stage` value silently falls through and runs the full “all” pipeline (verified by running `--stage bogus`: it printed `Analyzing …` and produced a report). This masks typos and violates least-surprise. → Recommendation: validate `stage` up front and return a usage error listing the accepted values.
- [severity: minor] [confidence: HIGH] `crates/codemorph-cli/src/commands.rs:719` / `verify` path — `--stage verify` silently does nothing if `migration-report.json` is missing or malformed. The only feedback is a generic stderr message on a read failure; a present-but-invalid report gives no per-file output. → Recommendation: print a clear error (and exit nonzero) when the report is missing/invalid, and report skipped (null-output) entries.
- [severity: minor] [confidence: MEDIUM] `crates/codemorph-cli/src/commands.rs:90-135` — output writes and status reporting use `is_ok()`/discarded results (e.g. `std::fs::write`, `std::fs::remove_file`) inside translation, so a filesystem failure can still yield `Compiled`/`Unsupported` without an error exit. → Recommendation: treat output/stage artifact write failure as `Failed` (or propagate and exit nonzero).
- [severity: minor] [confidence: HIGH] `README.md` install section vs repo — README says `python scripts/install_models.py --model-dir <artifact> --to models --role-name translator`, and AGENTS.md says transfer through `python scripts/install_models.py --from <artifacts> --to <product/models>`, but no `scripts/install_models.py` exists in this repository. The documented model-install path is unusable as written. → Recommendation: add the installer under `scripts/` (or correct the docs to the actual lab-side invocation) and keep the two variants consistent.
- [severity: minor] [confidence: HIGH] `docs/USAGE.md` stage list — omits the experimental `ffi` stage even though `commands.rs` (600-660) implements `--stage ffi` and specialized-models docs mention it. Minor but makes CLI help/docs diverge. → Recommendation: document `--stage ffi` status (experimental scaffold) and keep spelling consistent.
- [severity: minor] [confidence: HIGH] `crates/codemorph-project/src/lib.rs:28` and `crates/codemorph-models/src/lib.rs:47` — identical `hex` helper duplicated in two crates. → Recommendation: expose one `hex` from a shared crate (core or ir) and remove the duplicate.
- [severity: minor] [confidence: HIGH] `crates/codemorph-cli/src/commands.rs` — `collect_cpp_files` (1345) and `collect_rust_files` (1214) are two near-identical recursive walkers. → Recommendation: extract one parameterized `collect_files(root, extensions)` helper used by both.
- [severity: minor] [confidence: MEDIUM] `crates/codemorph-cli/src/translate.rs` — translator logic has only 8 unit tests; integration suite covers report shape, not translation correctness. No differential tests exercise full supported-subset matrix or a behavior mismatch beyond hello/unsupported. → Recommendation: add differential/contract tests against `docs/migration-engine.md` supported subset and a failing-behavior case assertion in `migrate_contract.rs`.
- [severity: minor] [confidence: MEDIUM] `crates/codemorph-cli/src/commands.rs` (role_model_generate prompt over argv) — trained-role prompts are passed via `--source-text` on the command line, risking `ARG_MAX` truncation; no documented maximum prompt size or stdin use. → Recommendation: pass prompts on stdin (as Ollama path already does) and document limits.
- [severity: minor] [confidence: LOW] `crates/codemorph-cli/src/commands.rs:289-375` — Python discovery probes `import torch`, and inference paths hard-import `torch`; unavailable PyTorch surfaces as child stderr after sandbox wait rather than upfront. → Recommendation: document the PyTorch requirement in `docs/inference.md` and report backend readiness in `models validate`.

## What I tried to break

- ✓ concurrent access / race conditions — CLI is single-process over local files; sandbox spawns isolated children; no shared mutable state except output paths. Not a concern in current scope.
- ✓ invalid/boundary input — empty input directory leaves a written empty report and `.codemorph` dir (works, prints “no source files found”); unrecognized `--stage` falls through to “all” (found). Unsupported C++ leaves no `.rs` as contracted.
- ✓ auth/permission bypass — no auth surface in product CLI.
- ✓ failure mid-operation — output/stage writes largely use `let _ =`/`ok()`, so partial/failure states are not propagated; report can claim success after write failures.
- ✓ contract shape — integration tests `migrate_contract.rs` (4 tests) all pass; shapes match documented keys for `--stage all` and `translate.json`.
- ✓ documentation drift — verified flags, `CODEMORPH_*` env vars, and stage values against code; found `ffi` omission and installer-script docs gap.
